# Gateway

The gateway is the server process that holds every model credential. It serves an OpenAI-compatible API, routes each request to a cloud provider or a local model, manages the model catalog and local model downloads, and, when built with them, serves web search, speech, and a browser settings page. It starts serving before any slow model work begins, and on desktop machines it runs from the system tray. The [gateway guide](https://cppalliance.org/runvil/gateway/) documents its configuration, profiles, and endpoints.

The Runvil installer ships the gateway as its Gateway component, and `runvil-gateway init` is what the installer runs: it writes the default configuration when none exists and downloads the speech runtime and models that configuration names, so a user can run it again to retry a failed download. A gateway running in the tray checks the release channel at start and every day, shows a newer version in its menu, and updates itself when asked, from the menu or through its `POST /update` route, which Workshop calls after its own update check. A gateway run with `--no-tray`, such as one started by the sample systemd unit in `packaging/gateway.service`, never checks on its own and is updated by rebuilding it, though it still applies an update when a local Workshop asks through `POST /update`.
